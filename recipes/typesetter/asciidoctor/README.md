# Asciidoctor (Typesetter)

Converts [AsciiDoc](https://asciidoc.org/) `.adoc` documents with the
[Asciidoctor](https://asciidoctor.org/) toolchain and exposes it to TeXlyre over
a local WebSocket compile bridge.

The Docker image layers Ruby, the Asciidoctor converter gems, and their common
external dependencies with the shared
[Chelys typesetter bridge](../../../bridge/1/README.md) and an AsciiDoc-specific
engine adapter (`engine.cjs`).

## One converter per format

AsciiDoc has no single renderer. Each output format is produced by its own
converter, and the adapter picks the right one:

| Format | Converter |
| --- | --- |
| PDF | `asciidoctor-pdf` |
| HTML | `asciidoctor` (html5 backend, `data-uri` for a single file) |
| EPUB | `asciidoctor-epub3` |
| reveal.js | `asciidoctor-revealjs` |
| DOCX | `asciidoctor` (docbook backend) piped through `pandoc` |

## Preview is PDF, everything else is Export

- **Compile tab**: PDF and Canvas (PDF).
- **Export**: PDF, HTML (single file), EPUB, reveal.js slides, Word (DOCX).

HTML is exported with `data-uri` so images are embedded and the download is one
self-contained file. reveal.js decks resolve the presentation framework from a
CDN by default, so set `revealjsdir` if you need them to work offline.

## Bundled tools

The image carries what AsciiDoc documents most often reach for:

- `asciidoctor-diagram` with Graphviz and a headless JRE, covering Graphviz,
  PlantUML, and ditaa blocks
- `asciidoctor-bibtex` for `bibtex-file` citations and bibliographies
- `asciidoctor-reducer` for flattening `include::` trees
- Rouge, CodeRay, and Pygments as source highlighters
- Ghostscript for the PDF optimizer, plus ImageMagick and `rsvg-convert`
- Pandoc for the DOCX path
- Noto and Liberation fonts, including CJK and colour emoji

Mermaid blocks need `mmdc` and a browser, which the image does not include. Other
converters, extensions, and PDF themes go in through the **Extra gems**
variable, which is appended to the gem install when the image is built.

## Modes

- **Docker** (recommended): builds an image containing Asciidoctor, the
  extensions above, and the bridge.
- **Connect**: point TeXlyre at an existing bridge you run yourself.

## Variables

- `wsPort`: port the compile bridge listens on (default `7047`).
- `gemPackages`: extra gems added into the image, e.g.
  `asciidoctor-kroki asciidoctor-lists`.

Changing `gemPackages` means the image no longer matches the published tag, so
Chelys builds it locally instead of pulling.

## Options

- **Document Type**: `article`, `book`, or `manpage`.
- **Attributes**: space-separated attributes passed as `-a`, for example
  `source-highlighter=rouge toc=left`.
- **Load diagram and bibtex extensions**: requires `asciidoctor-diagram` and
  `asciidoctor-bibtex`. Leave on unless a document conflicts with them.
- **Safe mode**: runs at `safe` rather than `unsafe`, keeping includes and
  generated diagrams inside the project directory.
- **Optimize PDF** (export): runs the Ghostscript-backed optimizer.

## Incremental sync

`typeConfig.incrementalSync` is enabled. The bridge keeps a per-connection
working tree and reconciles it against the manifest TeXlyre sends with each
request, so only changed files are transferred after the first compile and
diagrams generated by `asciidoctor-diagram` survive between builds. The tree is
discarded when the socket closes or when TeXlyre requests a cache clear.
